# ADR 0006: リリーススクリプトのタグ存在チェックを完全一致にする

- ステータス: 承認済み
- 日付: 2026-08-22
- 対象: `.github/scripts/create_release.sh`

## 背景

`v0.3.0-dev`（pre-release）のリリース後に `v0.3.0` をリリースしようとしたところ、
Release ワークフローが「タグが既に存在する」と判定して exit 1 で失敗した。
実際には `v0.3.0` のタグもリリースも作成されていなかった。

原因はタグ存在チェックの部分一致である。

```bash
if git ls-remote --tags origin | cut -f2 | grep -qF "refs/tags/$GIT_TAG"; then
```

`grep -F` は行全体ではなく部分文字列で照合するため、`refs/tags/v0.3.0` を探すと
既存の `refs/tags/v0.3.0-dev` の行にヒットする。SemVer の pre-release 版は
`X.Y.Z` に接尾辞を足した文字列であり、正式版のタグ名は必ず pre-release タグ名の
接頭辞になる。したがって「pre-release を出してから正式版を出す」という
本リポジトリの通常運用が、そのまま必ず踏むバグだった。

## 決定

パイプ + `grep` をやめ、`git ls-remote` に refspec を渡してリモート側で完全一致させる。

```bash
if [[ -n "$(git ls-remote --tags origin "refs/tags/$GIT_TAG")" ]]; then
```

`grep -qFx` で行全体一致にする案もあったが、こちらを採った。照合を `git` 自身に
任せることで「部分一致か完全一致か」という解釈の余地がなくなること、および
`set -o pipefail` 下で `grep -q` が入力を読み切らずにパイプを閉じ、上流の `git` が
SIGPIPE で落ちてスクリプトが誤って失敗しうる構造そのものを解消できることによる。

## 影響

- `v0.3.0` は未リリースであり、タグもリリースも残っていない。よってバージョンを
  上げる必要はなく、`package.json` は `0.3.0` のままとする。本修正のマージ後に
  main に対して Release ワークフローを再実行すればよい。
- 既存のタグ・リリース・配布物への影響はない。CI のチェックロジックのみの変更である。
- 「同一バージョンの二重リリースを防ぐ」というチェック本来の目的は維持される。
  完全一致に変わったことで、防ぐべきケース（真に同名のタグが存在する）だけを
  正しく検出するようになる。
