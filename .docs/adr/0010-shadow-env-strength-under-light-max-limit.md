# ADR 0010: `_ShadowEnvStrength` を 0.55 にする

- ステータス: 承認済み
- 日付: 2026-08-22
- 置き換え対象: [ADR 0008](0008-shadow-env-strength-one.md)

## 背景

[ADR 0008](0008-shadow-env-strength-one.md) では、lilToon のライト色を

```
lightColor = LIL_MAINLIGHT_COLOR + shMax
```

として `f = shMax`、すなわち `_ShadowEnvStrength` = `1.0` を導いた。
しかし実際のライト色はクランプを伴う。

```
lightColor = clamp(LIL_MAINLIGHT_COLOR + shMax, _LightMinLimit, _LightMaxLimit)
```

本プリセットは `_LightMaxLimit` = `1` を設定しているため、`L + A > 1` のワールドでは
`lightColor` が 1 に張り付く（`L`: 直接光、`A`: 環境光）。**ADR 0008 の導出はこのクランプを
見落としていた。**

実地検証において、環境光の明るいワールドで影が完全に消失することが確認された。
これは `A ≥ 1` のとき `f = saturate(shMin) = 1` と `lightColor = 1` が一致し、
`indirectCol` と `directCol` が同値になるために起こる。ただし症状が顕在化したのが
`A ≥ 1` だったというだけで、**ずれは全ての環境光量で同じ方向に生じていた**（後述の表を参照）。

### クランプ下での一致条件

`_ShadowColor` = `(0, 0, 0, 1)` のとき、正規化した出力は以下になる。

```
M    = min(L + A, _LightMaxLimit)
出力 = (f * (1 - G) + M * G) / M        … G: ADR 0007 のランプ出力、f = saturate(shMin * e)
理想 = (L * G + A) / (L + A)
```

クランプは露出制御とみなし、絶対輝度ではなく**相対コントラストの一致**を条件とする。
`_LightMaxLimit` はアバターの明るさ上限を担うプロパティであり、その効果を打ち消すことは
本 ADR の目的ではないためである。両者を等置すると

```
f / M = A / (L + A)
⇒ e   = M / (L + A)
```

`_LightMaxLimit` = `1`、`L` = `1` に正規化すると **`e = 1 / (1 + A)`** となる。
この条件は `G` に依存せず全階調で厳密に成立する。

| A（環境光） | 厳密な e | 検算: 最暗部 | 理想値 |
| --- | --- | --- | --- |
| 0.2 | 0.833 | 0.2235 | 0.2235 |
| 0.4 | 0.714 | 0.3344 | 0.3344 |
| 0.6 | 0.625 | 0.4176 | 0.4176 |
| 0.8 | 0.556 | 0.4823 | 0.4823 |
| 1.0 | 0.500 | 0.5341 | 0.5341 |

すなわち `e = 1.0` が正しいのは `_LightMaxLimit ≥ L + A` でクランプが効いていない場合に限られる。
クランプ下では `e = 1.0` は常に影を薄くしすぎており、その量は `A = 0.2` で +0.031、
`A = 0.6` で +0.210、`A = 1.0` で +0.466 に達する。

### 固定値の選定

`e` は環境光量に依存するが、マテリアルのプロパティ値は実行時に切り替えられないため
固定値を選ぶ必要がある。理想値からの乖離は以下の通り（正号は影が薄すぎることを意味する）。

| A | e=1.0 | e=0.8 | e=0.7 | **e=0.55** | e=0.5 |
| --- | --- | --- | --- | --- | --- |
| 0.2 | +0.031 | -0.006 | -0.025 | -0.053 | -0.062 |
| 0.4 | +0.106 | +0.032 | -0.005 | -0.061 | -0.080 |
| 0.6 | +0.210 | +0.098 | +0.042 | -0.042 | -0.070 |
| 0.8 | +0.331 | +0.182 | +0.108 | -0.004 | -0.041 |
| 1.0 | +0.466 | +0.280 | +0.186 | +0.047 | 0.000 |
| 1.2 | +0.424 | +0.237 | +0.144 | +0.004 | -0.042 |

`A ∈ [0, 1.2]` における最大乖離を最小化する値は `e = 0.56`（最大乖離 0.059）である。
`e = 0.55` でも最大乖離は 0.062 であり、[ADR 0007](0007-fix-shadow-strength-gamma-conversion.md)
の近似誤差 ±0.068 の範囲に収まる。プリセットの値としては桁を揃えた `0.55` を採用する。

## 決定

両プリセットの `_ShadowEnvStrength` を `0.55` とする。

- `Presets/half-lambert.asset`
- `Presets/half-lambert-with-backlight.asset`

`_LightMaxLimit` は `1` のまま維持する。
あわせて ADR 0008 のステータスを「ADR 0010 により置き換え」に更新する。

## 却下した案

### 案1: `e = 1.0` を維持し `_LightMaxLimit` を引き上げる

`e = 1.0` が正しくなる条件は `_LightMaxLimit ≥ L + A` である。`L = 1` として、
許容したい環境光量ごとに必要な値は以下になる。

| 許容環境光 A_max | 必要な `_LightMaxLimit` | 最明部の露出倍率 |
| --- | --- | --- |
| 0.4 | 1.4 | 1.40x |
| 0.6 | 1.6 | 1.60x |
| 1.0 | 2.0 | 2.00x |

却下理由は3点。

- `_LightMaxLimit` はアバター全体の明るさ上限を担う別責務のプロパティであり、
  影の都合で動かすとリムライトやマットキャップを含む見た目全般に影響する。
  「マテリアルを選ばず共通プリセットとして適用しても違和感が出ない」という
  本リポジトリの方針とも整合しない。
- 露出倍率がそのまま明るいワールドでの白飛びに直結する。
- `f = saturate(shMin * e)` が 1 で頭打ちになるため、`A > 1` では
  `_LightMaxLimit` を上げるほど影が理想値より濃くなる。完全な解決にはならない。

### 案2: `e = 1.0` のまま据え置き、ユーザーの個別調整に委ねる

却下理由: マテリアルのプロパティ値はワールドごとに切り替わらない。
Expression Menu でパラメータ化しない限り、ユーザーができるのは全ワールド共通の
妥協値を1つ選ぶことだけであり、それは本 ADR が行っている判断と同じである。
プリセットが担うべき判断の先送りにしかならない。

### 案3: 環境光量に応じた動的な補正

却下理由: `A / (L + A)` に相当する値をシェーダーに与える仕組みが lilToon に存在しない。
実現にはシェーダーの改造が必要であり、プリセットの範囲を超える。

## 影響

- **ADR 0008 の「環境光量に依らず ±0.068 で一定」という性質は成立しない。**
  `_LightMaxLimit` によるクランプがある限り、固定値では環境光依存の誤差が残る。
  `A ∈ [0, 1.2]` における最大乖離は 0.062。
- 明るいワールドで影が消失する問題は解消する。`A = 1.0` における最暗部は `0.581`
  （影の深さ 41.9%）となり、理想値 `0.534` に対する乖離は +0.047。
- 環境光のないシーン（`A = 0`）では挙動が変わらない。最暗部は ADR 0007 の `0.068` のまま。
- 既存マテリアルはプリセット適用時に値が焼き込まれているため、再適用が必要。
- `0.4.0` は `_ShadowEnvStrength` = `1` を含んだ状態で既にリリース済みである。
  挙動が変わる変更のため、本 ADR の内容は `0.5.0` としてリリースする。

## 既知の制限

- **`shMin` と `shMax` の乖離。** ADR 0008 と同様、`shMin < shMax` となるワールドでは
  復元量が不足し、影が理想値より濃く出る。安全側の誤差である。
- **`A > 1.2` では乖離が再び拡大する。** `f = saturate(shMin * e)` の頭打ちにより、
  `A ≥ 1/0.55 ≒ 1.82` 以降は `f` が `0.55` で固定される。
- **ForwardAdd パスには環境光の復元が入らない。** 加算パスに環境光を足すのは
  二重計上であり、これは正しい挙動である。
- **`_ShadowColor` が純黒であることが前提。** 純黒以外を設定すると `indirectCol` が
  `lightColor` 乗算後に 0 にならず、上記の導出が崩れる。
  > **注記 ([ADR 0011](0011-shadow-offset-back-to-shadow-color.md)):** この制限は
  > 中立グレーの `_ShadowColor` には当てはまらない。本 ADR の導出は `M = 1` を前提とした
  > 相対コントラストの一致条件であり、ADR 0011 が示した「切片オフセットを `_ShadowColor` に
  > 載せた場合と `_ShadowStrength` に載せた場合は `M = 1` で厳密に一致する」という等価性が
  > そのまま効くため、`_ShadowEnvStrength` = `0.55` は引き続き有効である。
  > 色相を付けた場合はチャンネルごとに切片がずれる点のみ、ADR 0011 の既知の制限を参照。
