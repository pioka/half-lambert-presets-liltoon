# ADR 0007: _ShadowStrength を 0.9319 に修正する

- ステータス: 承認済み
- 日付: 2026-08-22

## 背景

[ADR 0002](0002-strength-based-offset.md) で切片オフセットの表現を `_ShadowColor` から
`_ShadowStrength` へ移した際、以下の2つを等価として扱った。

- 変更前: `_ShadowColor` = `(0.2895, 0.2895, 0.2895, 1)`, `_ShadowStrength` = `1`
- 変更後: `_ShadowColor` = `(0, 0, 0, 1)`, `_ShadowStrength` = `0.7105`

根拠は `0.2895 + 0.7105 = 1` という算術だが、**この等価変換は成立しない**。
両者は異なる色空間の値であり、直接足し引きできない。

### Unity による `Color` プロパティのガンマ変換

Linear カラースペースのプロジェクトにおいて、Unity はシェーダーの `Color` 型プロパティを
アップロード時に sRGB → Linear 変換する。lilToon の宣言は以下の通りで、
`[Gamma]` や `[HDR]` といった変換を抑止する属性は付いていない。

```
_ShadowColor ("Shadow Color", Color) = (0.82,0.76,0.85,1.0)
```

したがって asset に記録された `0.2895` は sRGB 値であり、シェーダーに渡る時点では

```
sRGBToLinear(0.2895) = 0.06815
```

となる。一方 `_ShadowStrength` は以下の通り `Range(0, 1)` の float プロパティで、
このガンマ変換の対象外である（`LIL_COLORSPACE_GAMMA` が定義されている場合のみ
シェーダー側で `lilSRGBToLinear` に通されるが、Linear カラースペースでは通らない）。

```
_ShadowStrength ("sStrength", Range(0, 1)) = 1
```

つまり `_ShadowStrength` = `0.7105` が与える切片オフセットは Linear 値そのままの
`0.2895` であり、ADR 0002 の変更は影の最暗部を意図の約 4.25 倍
（`0.06815` → `0.2895`）に持ち上げていた。

### ADR 0002 の誤差表との不整合

ADR 0002 に記載された誤差表は、切片オフセットを Linear 値 `0.06815` として
計算したものである。表の各行は以下の式で再現できる。

```
近似値 = 0.06815 + 0.93185 * saturate((hL - 0.36945) / 0.63055)
```

すなわち**誤差表は正しく、実装だけが誤っていた**。表と実装が食い違ったまま
リリースされている状態である。

## 決定

両プリセットの `_ShadowStrength` を `0.7105` から `0.9319` に変更する。

- `Presets/half-lambert.asset`
- `Presets/half-lambert-with-backlight.asset`

`_ShadowColor` = `(0, 0, 0, 1)` は維持する。最暗部の明度は
`lerp(1, 0, 0.9319) = 0.0681` となり、ADR 0002 が意図した Linear 値と一致する。

## 検証

lilToon の実装（`lil_common_frag.hlsl`, `lil_common_functions.hlsl`）から、
影のランプは以下のように決まる。

```
hL       = saturate(dot(L, N) * 0.5 + 0.5)
borderMin = saturate(_ShadowBorder - _ShadowBlur * 0.5) = 0.36945
borderMax = saturate(_ShadowBorder + _ShadowBlur * 0.5) = 1.0   // 1.01195 が飽和
m        = saturate((hL - borderMin) / (borderMax - borderMin))
明度      = lerp(1, m, _ShadowStrength)
```

`_ShadowStrength` = `0.9319` における hL² との誤差は以下の通り。

| hL | hL² | プリセットによる近似値 | 誤差 |
| --- | --- | --- | --- |
| 0.000 | 0.000 | 0.068 | +0.068 |
| 0.369 | 0.136 | 0.068 | -0.068 |
| 0.739 | 0.546 | 0.614 | +0.068 |
| 1.000 | 1.000 | 1.000 | 0.000 |

誤差の符号が交互に反転しつつ絶対値が一致する等リプル状態であり、
このパラメータ形状における最良近似（Chebyshev 最適）であることが確認できる。
最大誤差は ±0.068 で、ADR 0002 の誤差表と一致する。

参考として、修正前の `_ShadowStrength` = `0.7105` では最大誤差が `0.290`（hL = 0）
まで悪化しており、hL² の近似として成立していなかった。

なお本誤差表は `_ShadowBorderColor` = `(0, 0, 0, 1)` を前提とする。本プリセットは
SSS 調の表現余地を残すためこのプロパティを意図的に設定しておらず、lilToon の既定値
`(1, 0.1, 0, 1)` のままのマテリアルでは影境界に色付きのグラデーションが加算されるため、
上記の誤差は保証されない。詳細は [ADR 0009](0009-shadow-border-color-out-of-scope.md) を参照。

## 影響

- **見た目が変わる。** 影が従来より濃くなる。ADR 0002 の「見た目は従来と等価であり、
  既存ユーザーへの影響はない」という記述は誤りであり、本 ADR で訂正する。
- 既存マテリアルはプリセット適用時に値が焼き込まれているため、パッケージ更新だけでは
  是正されない。修正を反映するにはプリセットの再適用が必要。
- 挙動が変わる変更のため、リリースは既存の `0.3.0-dev`（pre-release）に含める。
- ADR 0002 の理由「`_ShadowColor` が純黒になることで、ユーザーが影に色味を付けたい場合に
  オフセット量を壊さずに色だけを変更できる」は引き続き有効だが、
  ユーザーが `_ShadowColor` に純黒以外を設定した場合、その値もガンマ変換を受けた上で
  乗算されるため、切片オフセットは `_ShadowStrength` 単独では決まらなくなる。
  色味を付ける運用を案内する際はこの点に触れる必要がある。
